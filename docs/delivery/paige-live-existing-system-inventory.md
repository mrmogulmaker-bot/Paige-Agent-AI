Owner outcome: any authorized signed-in workspace user can tap the existing Talk live control, speak to Paige in that user's own thread and scope, hear the approved voice, interrupt it, and return to intact text chat. Availability is a separate platform-controlled rollout decision, not a role gate.

**Only necessary new storage:** a tenant-keyed platform availability row, default off, with no `anon` or `authenticated` table privileges and service-role-only writes. It answers only whether the workspace may enter Live audio. It does not hold roles, user context, transcripts, usage limits or provider keys. This is not a second tenant-feature system: existing tenant feature stores cannot safely own the third-party-audio rollout decision because customers can write them. Server functions read it after resolving the user and tenant; the relay rechecks before opening adapters. No account identity or pilot holder list belongs in this repository or its logs.

The per-user entitlement layer stays on the established path: authenticated user ID → active tenant and membership/role → caller-owned Paige thread → session and ticket bound to that actor and tenant → existing PAIGE runtime and governed permissions. The rollout row never grants access to a user by itself.

## Single-spine attachment map

This is the attachment plan for the **same** Live flow, not a second runtime. Every shared layer applies. The S2 Flux route and pilot gate do not yet speak or invoke the runtime; the join slice must connect them before any Live claim.

| Shared layer | Existing attachment point | Live use and boundary |
| --- | --- | --- |
| Harness and reasoning | `supabase/functions/paige-ai-chat/index.ts`, already called by `PaigeAIChat.tsx`; `PaigeLiveConversation.tsx` receives that component's thread, transcript, card and governed callbacks. | Feed final spoken text into this same caller-scoped turn path. Speak only PAIGE-authored output; no hosted agent, second model brain, or voice-specific chat handler. |
| Spine and authority | `supabase/functions/_shared/paige-spine/registry.ts`, `governedExecution.ts`, and the existing `paige-ai-chat` action-risk/approval path. | **UNAVAILABLE for this S2 transport/availability slice:** no Live Conversation `domain.capability` key is registered or claimed because no voice turn reaches the runtime yet. S4 must feed final voice text into the existing chat runtime and reuse each actual governed tool's registered key. A spoken “yes” is conversation input, never the UI approval callback or a second confirmation channel. |
| Rail and receipts | The existing `paige-ai-chat` `record_rail_event` and `paige_audit_log` paths after governed tool results. | Use the same verified action readback and receipt path; microphone frames, partial transcripts and synthetic “worked” events create no action receipt. |
| Mind | `_shared/paige-spine/chatEvidence.ts` imports `mindEvidence.ts`; `paige-ai-chat` calls `loadSpineEvidenceForChat`. | The same scoped Mind evidence is assembled by the runtime; the relay stores no separate thought or Mind state. |

| Tenant-relative knowledge | `paige-ai-chat`'s `match_rag_documents` retrieval and `rag_documents` source checks, plus its existing `client_memory` client/user scoping. | Retrieval stays inside the runtime's server-resolved tenant/user/client scope; the relay makes no parallel RAG query or knowledge index. |

| Identity and scope | `useTenantContext` / `useScopedUserId` / `usePaigeThreads` in the browser; `paige-live-session` calls `auth.getUser` and `current_user_tenant_id()`, verifies the caller-owned thread, and binds `actor_user_id`, `tenant_id`, `thread_id`, and `context_epoch` into `paige_live_sessions`; `paige-live-relay` consumes the one-use ticket and rechecks the thread, current workspace and the canonical direct-member/agency-child/agency-team/platform standing alternatives. | No browser-supplied tenant ID or role is authority. Workspace switch invalidates the scope epoch; no voice turn or memory read/write crosses a user's or tenant's boundary. |

The platform-only availability row is a narrow consent-rollout gate ahead of audio, not an alternative Spine, entitlement, tenant state store, or memory. The existing tenant-writable feature stores cannot enforce this decision, and the SQL wrong-role test proves the new row cannot be written by a tenant admin.

Proof boundaries: the production screenshots establish the rendered existing control and unavailable stage, not real audio. Local provider-free smokes establish ticket/relay ordering, not Deepgram account opt-out, ElevenLabs privacy, voice quality, latency, or a production conversation. Those require separate actual-provider and human checks before claiming Live Conversation delivered.
